# Test catalogue

Run with `cd backend && python -m pytest`. There are 163 tests. Each test uses a fresh temporary SQLite database and fictional people (Ana Villanueva and beneficiaries Carla, Ben and Dina). The Prolog and AI tests need `swipl`.

| Required area | File | What is covered |
|---|---|---|
| All writing modes | `test_writing_modes.py` | Registry polymorphism; Verbatim, Light Fix and Review outputs; clean text; originals preserved in storage; accepting a review via the API; preview does not save |
| Entry processing | `test_processing.py` | normalize (whitespace, smart quotes, NFC, idempotence); extract (names, topics, hashtags, frozen results); correct (rules, reporting, input not mutated); diff (round-trip, identical texts); deterministic summary |
| Hash-chain integrity | `test_hashchain.py` | Valid chain; modification and deletion detected; entries and revisions linked; ORM refuses update and delete; DB trigger refuses raw UPDATE; tampering after dropping the trigger detected (also through the API); policy and audit chains |
| Valid / invalid policy statements | `test_policy_language.py` | Lexer tokens and errors; all three samples compile; all four statement types; 8 syntax errors; error recovery; 8 semantic errors; domain rules built; warnings; Prolog translation with escaping; JSON round-trip |
| Prolog access rules | `test_prolog_rules.py` | Nothing shared while the owner is alive (whatever the policy says), also through the overview, letters and assistant endpoints; owner previews show the after-death view; deny by default; existence, summary and verbatim levels; highest grant wins; matrix endpoint |
| Release dates | `test_prolog_rules.py` | `from`/`until` filters; `after DATE` closed the day before and open on the day; after-death release |
| Conflicting permissions | `test_prolog_rules.py` | A deny beats an allow even when the allow comes later; group vs individual vs `everyone` |
| Unauthorized beneficiaries | `test_prolog_rules.py`, `test_api_security.py` | Unknown or deactivated handles get nothing; deactivated users locked out; neutral answer and no letters; letters only reach their recipient; role isolation between owners |
| AI citations | `test_ai.py` | Citations match retrieved entries; summary-level citations; made-up and existence-only citations are stripped |
| AI information leakage | `test_ai.py` | A spy provider and an adversarial "greedy" model that requests every id never receive unauthorised text; the rest of a summary-level entry's text never reaches the model; existence reveals the date only; denied and missing are indistinguishable; letters are never sent to the model; the model is not called when nothing is authorised; the leak guard blocks a simulated bug |
| Executor report and waiting period | `test_executor.py` | Only the chosen executor can report (password + phrase); the owner is emailed; nothing happens during the wait; “I'm still here” cancels; the executor can withdraw; the trigger activates after the wait (vault sealed, policy frozen, beneficiaries emailed); cancelled reports never activate; executor must be the owner's own activated beneficiary; no reports after sealing |
| Death-trigger email notices | `test_death_notices.py` | Only beneficiaries with something released are emailed; no diary content in any email; un-activated beneficiaries receive a working invite code; outbox and retry without SMTP; SMTP failure keeps the trigger; audit and owner scoping |
| Email verification | `test_email_verification.py` | No use before verification; correct code signs in; 5-attempt limit; expiry; resend rate limit and code replacement; no email enumeration; unfinished sign-ups do not block the real owner; verified emails cannot be re-registered; code hidden unless the development flag is on; existing accounts migrated as verified |
| Password reset | `test_password_recovery.py` | Code emailed and resets the password; works for beneficiaries; same answer for unknown emails; single use, 5-attempt limit, expiry, resend limit; reset signs out every device; changing the password keeps this device and signs out others; weak passwords refused; inactive or unverified accounts cannot reset; audit; old databases upgraded |
| Security extras | `test_api_security.py` | scrypt hashing, registration and login, weak passwords, 401 on every protected route, invite flow (single-use), handle validation, death trigger (password, phrase, irreversible, seals the vault), audit coverage |
| Handout "Try It Yourself" table (Maria, after the death trigger) | `test_handout_scenarios.py` | "Did he ever write about me?" gives the count only; family question gives summaries with dates; the letter is refused before 2040-05-01 and shown verbatim after; business question and a person with no protocol get the same neutral reply; hidden text never reaches the model; other people never receive Maria's letter; an ambiguous name shares nothing (`AmbiguousName`) |
